# Y 形摆交互式模拟器 —— 使用说明

> 用手拖动滑条改参数，右边立刻看到**真实物理动画**和**同步的二维轨迹图**。

---

## 1. 怎么启动

需要 Python 3.8+ 与 tkinter（Python 官方安装包自带）。本机已装好依赖，
用项目一直在用的解释器即可：

```powershell
& "<local path> `
  "<repo>/
```

如果 `python` 已在 PATH 上，也可以直接：

```powershell
python ypendulum_gui.py
```

**不确认能否启动时**，先跑一次自检（建窗、改参数、跑 30 帧后自动退出）：

```powershell
python ypendulum_gui.py --smoke
```

## 2. 界面怎么看

界面右侧是**两个标签页**：

| 标签页 | 内容 |
|---|---|
| **① 动画 + 二维轨迹** | **侧视动画与二维轨迹同屏**：左边是下视 Lissajous 图案 + 包络图，右边是侧视真实物理动画 |
| **② 3D 自由视角** | 可任意旋转的立体视图，从任何角度看摆动 |

```
┌────────────────────────────────┬──────────────┐
│ ② 下视：与动画同步的二维轨迹      │ ① 侧视动画   │
│    （Lissajous 图案）            │              │
│         ● ← 当前摆球位置          │  A₁ ── A₂   │
│                                  │    \  /      │
│                                  │     ● K      │
├────────────────────────────────┤     │        │
│ ③ 包络：|x|（红）与 |y|（蓝）的拍  │     ● P      │
└────────────────────────────────┴──────────────┘
```

两个视图**共用同一个摆球、逐帧同步**：侧视图里摆球正在往哪边摆，
左边的轨迹图就同时把这一笔加在对应位置 —— 正好可以对照"侧视看到的往复"
和"下视看到的图案"其实是同一件事。

左侧的控制面板两个标签页都可见；切到 3D 标签页时，摆球仍是同一个。

### ① 标签页里的三块画布

- **下视轨迹**（左上，最大）：题目说的 Lissajous 图案。蓝点就是此刻摆球的位置；
  左下角实时显示满量程、轨迹点数、`f_r` 与 `T_beat`。
- **包络图**（左下）：最近一段时间的 |x(t)| 与 |y(t)|，可以直观看到"拍"的存在。
- **侧视动画**（右侧竖条）：从侧面看真实装置——两根上臂 + 结点 + 摆球，带余辉。
  能看出摆球在**面内**（x）与**面外**（y）两个方向同时运动、振幅此消彼长。

三块画布按比例分配宽度（约 34:11）与高度（1:1），**窗口缩放时一起按比例变化**，
最小尺寸下也不会把任何一块挤没。

### ② 3D 视角怎么操作

| 操作 | 效果 |
|---|---|
| **按住左键拖动** | 绕装置旋转（左右改方位角，上下改仰角，−88°～+88°） |
| **滚轮** | 缩放（0.25×～4×） |
| **双击** | 复位到默认视角（方位 38°、仰角 24°） |
| **「自动旋转」勾选框** | 让视角缓慢自转，适合一边讲一边放着看 |
| **「显示轨迹」勾选框** | 开关三维空间里的运动轨迹 |

**关于 3D 视图的一个几何事实**：屏幕上的竖直高度 ∝ sin(仰角)。
所以仰角调到 0°（完全水平看）时，整个装置会压成一条水平线 —— 这不是 bug，
而是正对着边缘看一个竖直悬挂物的必然结果。**默认的 24° 仰角**是让装置
占满画面约 50% 高度的平衡点；把仰角抬到 65° 左右最方便俯视观察图案。

### 左侧读数面板

`h`、`f_in`、`f_out`、`f_r`、`T_beat`、`x_slack`、当前时刻与位移，
全部**随滑条实时更新**，两个标签页都看得到。

### 缩放：换什么参数都能完整看到摆

左侧面板有**「显示缩放」**一栏，三种模式：

| 模式 | 行为 | 什么时候用 |
|---|---|---|
| **仅装置**（默认） | 自动调整，让整台装置（天花板锚点 → 摆球）始终完整可见 | 平时观察；画面稳定，不会因为轨迹长大而忽大忽小 |
| **适配轨迹** | 自动调整，把**整条 Lissajous 轨迹**也框进画面 | 想看完整图案；轨迹长大时画面会自动缩小 |
| **手动** | 由滑条控制，0.25×–4× | 想盯住某个细节（例如只看结点附近） |

**为什么需要它**：装置尺寸随参数变化极大 —— `L = 0.10 m` 的摆只有约 0.19 m 高，
`L = 0.90 m` 的有约 1.14 m 高，相差 6 倍；`R` 从 0.06 m 到 0.22 m 时水平张角也差 4 倍。
固定比例必然在某些参数下把摆挤出画面。自动模式会根据当前几何实时算出合适的比例。

侧视与二维轨迹**各自按自己的画布长宽比**算比例（侧视画布高而窄、轨迹画布接近方形），
所以两个视图都能各自填满，不会因为另一个被裁而受损。

右侧的**倍数读数**在两个自动模式下会分别显示「侧视 xx px/m / 轨迹 xx px/m」，
手动模式下显示当前的 × 倍数（例如 `2.00×（手动）`）。

另外：

- **+/−** 按钮每按一次乘/除 1.25；按 **+** 会自动切到手动模式（否则和自动模式冲突）。
- **3D 视图**的滚轮是在左侧倍率之上再叠一个系数（1.15 倍/格），不影响另外两个视图。
- 手动模式下 **1.00×** 的含义是"装置恰好铺满视图"，调大就是放大细看。

## 3. 每个参数在物理上干什么

| 参数 | 物理作用 | 对 `f_r` 的影响 |
|---|---|---|
| **上臂长 l** | 决定结点深度 `h = √(l²−R²)` | l 越大 → h 越大 → `f_out` 越低 → **`f_r` 变大** |
| **孔距半值 R** | 两个上孔间距的一半 | R 越大 → h 越小 → `f_out` 越高 → **`f_r` 变小**；R→l 时 h→0，两模趋于简并 |
| **下臂长 L** | 摆球到结点的距离 | L 越大 → 两个频率都降低，**`f_r` 变小**；L 很小时 `f_r` 很大 |
| **结点质量 m_K** | 结点的惯性 | **`f_in` 完全不变**（面内结点没有自由度）；`f_out` **略微升高** → `f_r` 略降 |
| **释放振幅 A** | 初始条件 | 大振幅下两模都**变慢**，但面内模变慢更多 → 频率差变小 → **`T_beat` 变长** |
| **释放方位 ψ₀** | 初始条件 | 0° 只激发面内模（走直线）；90° 只激发面外模；45° 两模等幅（图案最饱满） |
| **阻尼 b** | 能量耗散 | 图案逐渐收缩；两个模的衰减速率不同 → 图案偏向衰减慢的模 |
| **时间倍率** | 仅为观察方便 | 不改变物理 |

### 主控律（界面里 `f_r` 的来源）

    f_r = f_in / f_out ,   f_in = (1/2π)√(g/L) ,   f_out = (1/2π)√(g/(L+h)) ,   h = √(l²−R²)
    ⇒  f_r = √(1 + h/L)

## 4. 建议的演示流程（5 分钟讲完整个物理）

1. **先看参考几何**：点"参考几何"预设。侧视看到 Y 形结构，下视看到一个**缓慢旋转的矩形/椭圆**
   —— 这就是 Lissajous 图案。读数显示 `f_r ≈ 1.345`、`T_beat ≈ 4.3 s`。
2. **只动一个旋钮**：把 **R** 从 0.060 慢慢拉到 0.240。
   观察 `f_r` 从 1.345 降到 1.11，图案从"旋进矩形"变成"几乎不动的扁椭圆"。
   > 这就是题目问的"图案如何依赖参数"。
3. **看两个极端**：
   - 点"1:1 简并"（R 接近 l）：`f_r → 1`，图案**不再旋进**，退化成球面摆。
   - 点"短下臂"（L = 0.10 m）：`f_r ≈ 1.85`，图案变成明显的 8 字形/多重花瓣。
4. **看隐藏自由度**（本方案的核心创新）：
   在"结点约束状态"里切到**滑环**——同样的几何，`f_r` 变成 1.0136，`T_beat` 变成约 110 s，
   图案在几十秒内几乎不动；再切到**三弦三脚架**——`f_r` 严格等于 1，图案是一条**永不旋进**的直线。
   > 题面没说结点能不能滑动，而它让 `f_r` 相差 33%。
5. **看振幅效应**：把 **A** 从 0.005 拉到 0.060。
   读数里 `T_beat` 从 4.291 s 变到 4.327 s（变长）——这是报告里主推的可证伪预言。
   注意 `x_slack ≈ 74 mm`：A 超过它会弹出"一根上臂松弛"的警告。
6. **看结点质量**：把 **m_K** 从 0 拉到 5 g。
   `f_in` **一动不动**，`f_out` 缓慢升高，`f_r` 随之下降——这是报告里反直觉的那条预言。

## 5. 程序如何保证"动画里的物理就是报告里的物理"

模拟器不是随手画的动画。`ypendulum_sim.py` 里的模型与报告一致：

| 环节 | 做法 |
|---|---|
| 两个模的频率 | 解析式 `√(g/L)` 与 `√(g/(L+h))`，与报告 §1.4 完全一致 |
| 面内/面外解耦 | 由"结点被约束锁死"的定理给出（报告 §1.3） |
| 振幅非线性 | 用精确单摆的椭圆积分展开 `f(A)/f₀ = 1 − A²/(16L²) − 11A⁴/(3072L⁴)` 反解成 Duffing 系数 |
| 模间耦合 | 系数由**完整非线性动力学的直接积分**标定（`theory-modeler` 的 `nonlinear_check.py`） |
| 结点质量 | `f_in` 与 μ 无关；`f_out` 按 `(1+μa)/(1+μa²)` 升高，`a = h/(L+h)` |
| 松弛阈值 | `x_c = R·L/h`，超过就告警 |

**自检可以直接跑**：

```powershell
python ypendulum_sim.py --selftest     # 物理引擎
python verify_3d.py                    # 3D 投影数学
python ypendulum_gui.py --smoke        # 界面：建窗、改参数、跑帧、三个标签页各画一遍、拖动/缩放/复位
```

- `--selftest` 核对：参考几何的 `f_in/f_r`、三态对照、结点质量的两条预言、
  时间步进的能量守恒（<10⁻³）、以及**大振幅频移是否复现椭圆积分律**
  （实测 6.5×10⁻⁷ 相对差）。全部通过才打印 `SELFTEST: PASS`。
- `verify_3d.py` 核对 3D 投影：相机基正交归一、与独立写出的解析透视式逐点比对
  （最大偏差 0）、各向同性（奇异值比 1.0000）、56 个视角下装置全部不出界、
  深度单调且尺度 ∝ 1/深度、极端仰角不退化。全部通过才打印 `VERIFY 3D: PASS`。
- `--smoke` 核对界面：三个标签页的图元数、拖动/缩放是否真的改变视角、复位是否回到默认值，
  以及**缩放**：手动滑条是否线性作用、自动模式在 5 组差别很大的参数下是否都框得住内容、
  自动换算系数是否随参数合理变化。

另外三个无界面命令：

```powershell
python ypendulum_sim.py --export traj.png   # 跑 30 s 并导出二维轨迹图
python demo_three_states.py                  # 生成三态对照图
python capture_3d.py                         # 导出 4 个典型 3D 视角（需要 Ghostscript）
```

## 7. 已知限制（诚实说明）

1. **动画用的是"有效摆长"模型**，不是把每根弦的约束方程逐点数值求解。
   它复现了两个简正模的频率、振幅非线性、模间耦合与结点质量效应，
   但不包含弦的弹性伸缩、结点的快速内部振动（约 13.6 Hz）、以及摩擦粘滑。
2. **滑环态只是定性演示**：该态的面内频率与几何的精确关系没有像系结态那样解析建立，
   程序里按项目文档给出的参考值（`f_r = 1.0136`）锚定并随 L 缩放。
3. **振幅超过 `x_c = R·L/h` 后模型失效**（一根上臂会松弛），
   程序会告警但仍继续跑，仅供演示——**不要用那段区间的数据下结论**。
4. 侧视图把三维运动投影到二维，摆球在面外的位移看起来会略小于真实值。
